# Canonical Financial-Data Schema

This document defines the strict data schema required by the FinOmaly ingestion pipeline. Any uploaded CSV or Excel file must contain or be mapped to these exact data points to calculate the Beneish M-Score.

## Metadata & Context
Company and Organization associations are handled externally via the upload API (using `company_id`). The file itself only needs to define the time period and the financial variables.

### Financial Year (FY)
- **Description:** The specific financial period for the column/record (e.g., "FY2023", "FY2024"). 
- **Requirement:** The ingestion pipeline requires at least two consecutive years (Target Year and Prior Year) to compute the year-over-year M-Score indicators. Both years must be supplied correctly for each indicator calculation.
- **Currency and Scale:** Before any values are stored or compared across years, the ingestion pipeline must standardize currency and scale (e.g., converting everything to raw USD). If source statements use different currencies, accurate conversion is required before calculating indicators.

## The 13 Canonical Variables

The following 13 numeric variables must be extracted for every valid Financial Year. 

### Income Statement
| # | Variable | Description |
|---|---|---|
| 1 | **Net Sales / Revenue** | Total operating revenue net of discounts and returns. |
| 2 | **Cost of Goods Sold (COGS)** | Direct costs attributable to the production of the goods sold. |
| 3 | **SG&A Expense** | Selling, General, and Administrative expenses. |
| 4 | **Depreciation** | Depreciation and amortization expense for the period. |
| 5 | **Income from Continuing Operations** | Required for the TATA calculation (do not use generic Net Income if it includes discontinued operations). |

### Balance Sheet
| # | Variable | Description |
|---|---|---|
| 6 | **Accounts Receivable** | Money owed to the company by its debtors. |
| 7 | **Current Assets** | Assets expected to be converted to cash within one year. |
| 8 | **Property, Plant, and Equipment (PPE)** | Long-term tangible assets (net of depreciation). |
| 9 | **Total Assets** | Sum of all short-term and long-term assets. |
| 10 | **Current Liabilities** | Debts or obligations due within one year. |
| 11 | **Long-Term Debt** | Loans and financial obligations lasting over one year. |
| 12 | **Total Liabilities** | Total of all liabilities. (Required for LVGI. Do not simply sum current liabilities and long-term debt, as other liabilities may exist). |

### Cash Flow Statement
| # | Variable | Description |
|---|---|---|
| 13 | **Cash Flow from Operations (CFO)** | Net cash generated by the company's regular business operations. |

## Missing Data Handling (Graceful Degradation)

Financial documents are frequently incomplete. The ingestion pipeline and calculation service must handle missing variables gracefully without crashing, while preserving the mathematical integrity of the Beneish M-Score.

### 1. Database Storage
- The `financial_statements` table allows `NULL` (Optional) values for all numeric variables. 
- Incomplete uploads are immediately saved to the database to preserve user progress, rather than forcing a stateless, in-memory correction loop.

### 2. Calculation Rules
- **Never Fake Data:** Never substitute a missing value with `0` (this destroys the statistical regression model).
- **Calculate What Is Possible:** The Calculation Service will compute individual indicators (e.g., GMI, AQI) if their specific required variables are present in the data across both the current and prior years.
- **Fail Gracefully:** If an indicator is missing an input, that specific indicator's result evaluates to `null`.
- **Strict Final Score Block:** A partially computed set of indicators must **never** be mistaken for a valid final M-Score. Because the final M-Score is the sum of all 8 indicators multiplied by their coefficients, if even one indicator evaluates to `null`, the final M-Score explicitly evaluates to `null` (or Incomplete).

### 3. Frontend UX
- The frontend will display the successfully computed indicators normally.
- For indicators that failed due to missing inputs, the UI will display a distinct "Missing Data" state.
- The main M-Score Gauge will be replaced by a strict "Incomplete Data" prompt, indicating that the final score cannot be calculated until a complete financial file is uploaded.
